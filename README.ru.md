# Jev Router

**Каждому запросу — подходящий маршрут. Каждому субагенту — понятная задача.**

Jev Codex Router подключает [Jev от TypeSafe](https://docs.typesafe.ai/sdk/python/) к Codex: классифицирует запрос, подбирает профили исполнения и помогает распределять независимые части работы между субагентами. Вы пишете обычный запрос — hook запускает маршрутизацию перед его обработкой.

[English](README.md) · [Настройка](docs/CONFIGURATION.md) · [Каталог критериев](docs/PROMPTS.md) · [Проверки](docs/TESTING.md)

Независимый open source проект, не официальный продукт OpenAI или TypeSafe. **Ранняя версия:** локальная логика и установка проверены; точность живого Jev и полный цикл делегирования внутри Codex ещё требуют проверки. Обещаний измеренной экономии токенов нет.

## Что это даёт

- **Автоматическая маршрутизация.** Не нужно каждый раз писать название навыка.
- **Модель подбирается под работу.** 14 категорий, 7 профилей, открытые критерии.
- **Команда с ответственным руководителем.** Основной Codex назначает задачи специалистам, следит за зависимостями и принимает результат. Независимые части можно выполнять параллельно, связанные изменения остаются у одного исполнителя.
- **Постоянная установка.** Окружение, навык, профили, hook и управляемое правило в глобальном `AGENTS.md` устанавливаются одним скриптом. Ключ можно ввести один раз.
- **Видимая неопределённость.** Неясный запрос не приводит к автоматическому выбору самой мощной модели.
- **Приоритет Luna/Sol.** Ограниченные задачи получают достаточный профиль; новое назначение Astra требует обоснования в планировщике.
- **Поиск и обмен сообщениями.** Агенты выбирают источник недостающих данных и передают коллегам вопросы и результаты через доступные инструменты Codex. [Командная работа](docs/TEAMWORK.md).

## Обновление

Когда в репозитории появятся новые изменения, вставьте в свой локальный Codex:

```text
Обнови установленный Jev Router из https://github.com/Madikhan33/jev_codex.
Найди папку исходников, прочитай README и проверь установщик. Перед получением
и применением обновлений сохрани резервную копию локальных изменений;
не удаляй их и не выполняй принудительный сброс. Если исходников нет,
клонируй репозиторий в отдельную папку.
Запусти install.py --without-key через Python 3.11+, затем run.py doctor.
Сохрани API-ключ, настройки, другие хуки и пользовательские инструкции агентов.
Сравни установленный каталог классификатора с новыми промптами проекта.
Сделай резервную копию каталога перед объединением изменений, сохрани мои
критерии и сообщи о конфликтах. Не спрашивай ключ в чате.
Расскажи, что обновилось и какие шаги остались: перезапуск Codex
и проверка /hooks, если потребуется повторное доверие.
```

Для ручного обновления откройте терминал **в папке исходников**, проверьте
`git status` и сначала закоммитьте или сохраните копию локальных изменений.
В чистом рабочем дереве выполните:

```powershell
git pull --ff-only
py -3 install.py --without-key
py -3 run.py doctor
```

На macOS/Linux используйте `python3` вместо `py -3`. Если вы сами изменили
исходники и хотите применить их, пропустите `git pull` и выполните две команды
Python. Если проект скачан ZIP-архивом, вместо `git pull` распакуйте свежую
версию в отдельную папку.

**Одного `git pull` недостаточно:** установщик должен скопировать изменения
в рабочую среду Codex. Обновление запускается вручную, фонового автообновления нет.
После установки перезапустите Codex. Изменённый hook может потребовать повторного
доверия в `/hooks`. Ключ, настройки и пользовательский каталог сохраняются;
явное отключение контекста сохраняется. Если настройка отсутствует, контекст включён по умолчанию.

**Отдельно обновляются промпты классификатора:** повторная установка сохраняет
каталог, поэтому новые критерии из `jev_router/prompts/` не заменяют старые файлы.
Сделайте копию `%USERPROFILE%\.codex\jev-router\catalog` на Windows или
`~/.codex/jev-router/catalog` на macOS/Linux, затем сравните и объедините изменения
промптов и политики. При нестандартной установке используйте её фактический путь.
Промпт для Codex выше уже включает этот шаг. Если вручную изменён управляемый файл
навыка или агента, установщик может остановиться, защищая правки: сначала разрешите
указанный конфликт. Через GitHub доступны только опубликованные изменения.

## Установка одной командой

**Ищете промпты UI и backend?** Они в [jev_router/prompts/](jev_router/prompts/README.md):
[категории](jev_router/prompts/domains.toml), [профили моделей](jev_router/prompts/profiles.toml),
[общие правила](jev_router/prompts/routing.toml). Команда `py -3 run.py prompts --category backend_api`
покажет реальный вопрос без ключа и без вызова API.

Нужны Python **3.11+**, интернет, ключ TypeSafe и локальный Codex с поддержкой [hooks](https://learn.chatgpt.com/docs/hooks) и [субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Скачайте проект, откройте терминал в его папке и выполните:

```powershell
# Windows
py -3 install.py
```

```sh
# macOS / Linux
python3 install.py
```

Установщик создаст отдельное окружение, установит SDK, скопирует навык, создаст семь профилей агентов, добавит hook и управляемое правило в глобальный `~/.codex/AGENTS.md`. Остальные инструкции и настройки сохраняются. Перезапустите Codex, чтобы правило применилось к новым задачам.

1. Введите ключ TypeSafe в скрытом приглашении терминала.
2. Перезапустите Codex, откройте `/hooks`, проверьте и разрешите **Jev Router**.
3. Напишите задачу: «Добавь панель карточек и API создания и просмотра».

Разрешение hook — обязательный шаг самого Codex. Установщик не обходит его. Один файл навыка без hook не перехватывает каждый запрос.

### Установка через промпт

Вставьте этот промпт в локальный Codex — заранее скачивать проект не нужно:

```text
Установи https://github.com/Madikhan33/jev_codex для моего локального Codex
и настрой автоматическое использование Jev Router для следующих запросов.
Склонируй репозиторий в отдельную папку, прочитай README и проверь установщик.
Запусти install.py --without-key подходящим Python, сохранив мои настройки.
Проверь установку через run.py doctor. Для ключа покажи готовую команду
run.py configure с полным путём; не проси присылать ключ в чат.
Объясни перезапуск Codex и разрешение Jev Router в /hooks.
Если настройка не завершена, явно укажи оставшиеся шаги.
```

Этот способ станет доступен после публикации кода в указанном репозитории.
Codex выполнит установку; пользователю останется ввести ключ в терминале,
перезапустить Codex и разрешить hook. До ввода ключа `doctor` сообщит,
что настройка не завершена. Для уже скачанного проекта замените ссылку
в промпте на путь к его папке и пропустите клонирование.

После публикации этой версии, при установленных uv и Git:

До отправки кода на GitHub используйте локальную папку. Это установка из Git, а не из PyPI. Для воспроизводимости после `.git@` можно указать опубликованный тег или commit.

## Где указать ключ, чтобы он сохранялся

Получите ключ в [аккаунте TypeSafe](https://typesafe.ai/); [документация SDK](https://docs.typesafe.ai/sdk/python/) описывает подключение. Подписка ChatGPT или ключ OpenAI его не заменяют.

Проще всего ввести его при установке. Ключ сохранится вне проекта:

| Система | Файл по умолчанию |
| --- | --- |
| Windows | `%USERPROFILE%\.codex\jev-router\secrets.json` |
| macOS / Linux | `~/.codex/jev-router/secrets.json` |

`CODEX_HOME` меняет папку `.codex`. Чтобы добавить ключ после `--without-key` или заменить старый:

```powershell
py -3 run.py configure
```

На macOS/Linux: `python3 run.py configure`. Ввод скрыт. Перезапуск компьютера не удаляет ключ. Отозванный или истёкший ключ нужно заменить.

**Ключ хранится открытым текстом.** На Unix права файла — `0600`, на Windows действуют права папки пользователя. Это не зашифрованное хранилище. [Безопасность](SECURITY.md).

Альтернатива — `TYPESAFE_API_KEY` в окружении или менеджере секретов. Переменная имеет приоритет над файлом; Codex должен получать её при каждом запуске. Переменная терминала не появится автоматически в уже открытом приложении. `.env` автоматически не читается. Не присылайте ключ в чат и не добавляйте в Git.

## Как обрабатывается запрос

```text
Запрос → UserPromptSubmit hook → Jev: категории и намерение
       → Jev: профили → Python: проверка и группы владения
       → Codex + навык → подзадачи и субагенты → интеграция и проверки
```

Первый вызов содержит 14 вопросов о категориях и три управляющих вопроса. Второй выбирает профили только для найденной работы. Если категорий нет, второго вызова нет. Категории используют `Noul`, профили — `Choice`.

Для задачи «Сделай фон светлее, добавь панель карточек и API» ожидается:

| Работа | Исполнитель | Пример профиля |
| --- | --- | --- |
| Фон, панель, подключение API | Интерфейс | Sol / medium |
| API создания и просмотра | Сервер | Sol / medium |

Это иллюстрация политики, не записанный ответ Jev. Codex согласует контракт, выполняет одну часть и передаёт другую субагенту, если среда позволяет. Для изменения цвета отдельный агент не нужен.

### Кто решает, кому поручить задачу

**Основной Codex — руководитель команды.** Jev рекомендует категории, профили и способ координации. Codex учитывает эти рекомендации, исходный запрос, историю разговора и код проекта, затем формулирует конкретные задания. В разговоре он ведёт короткий список: задача, ответственный, зависимости, статус и проверка готовности.

Каждый субагент получает ограниченный участок работы, ожидаемый результат и способ проверки. Он возвращает изменения, результаты проверок и нерешённые вопросы руководителю. Самостоятельно создавать следующую команду субагентов исполнители не должны. Основной Codex отвечает за согласование решений, объединение изменений и итоговую проверку.

Например, даже небольшую правку цвета основной Codex оформляет как конкретное задание одному Luna-субагенту, пока сам проверяет область изменений и критерии приёмки. В задаче с UI и API сначала согласуется контракт; только после этого независимые части могут выполняться параллельно. Зависимая задача ждёт результата предыдущей.

| Стратегия в ответе Jev Router | Что делает Codex |
| --- | --- |
| `single_agent` | Сам отвечает на вопрос или обрабатывает запрос вне разработки; подтверждённые правки передаются исполнителю |
| `resolve_scope` | Определяет задачу по контексту, если нет групп работы или уверенно распознанного намерения для исполнения |
| `assign_specialist` | Назначает одного специалиста для конкретной правки, включая небольшую |
| `consider_delegation` | Распределяет несколько групп, для которых подтверждена возможность раздельной работы |
| `coordinate_team` | Согласует контракты и зависимости нескольких групп до начала параллельных изменений |

**Неопределённость больше не означает остановку всей команды.** Если оформление интерфейса понятно, а изменение компоновки ещё под вопросом, Codex может продолжить понятную часть. `review_required` означает проверку рекомендации маршрутизатора, а не обязательный запрос к пользователю и не независимую проверку готового дизайна.

Пустой профиль тоже не запрещает делегирование: Codex может выбрать подходящий доступный профиль по локальному контексту, явно указав, что это его решение, а не рекомендация Jev. Поле `coordination` показывает способ координации; значение `unclear` сохраняется, если классификация не прошла порог уверенности. Доступность модели всё равно зависит от среды и аккаунта.

Это правила работы команды, а не доказательство успешного запуска всех сценариев: полный цикл на живом Jev и реальных субагентах ещё требует отдельной проверки.

Профили: Luna xhigh/max, Sol medium/high/xhigh, Astra low/medium. Их порядок — настройка политики, не измеренная цена или качество.

## Ограничения

- Hook **не переключает модель основного Codex**.
- Субагентов создаёт Codex по навыку, с учётом доступных инструментов и лимитов. Доступность моделей для аккаунта автоматически не проверяется.
- В TypeSafe передаётся текущий текст запроса, а при включённом контекстном режиме — также сохранённое краткое состояние задачи. Репозиторий, полный диалог, вложения и аудио автоматически не собираются. Автоматического удаления секретов из текста нет.
- Коротким уточнениям может понадобиться контекст самого Codex. Слишком длинные запросы и обычные управляющие команды пропускаются.
- При ошибке Jev появляется предупреждение, Codex продолжает обычную работу.

## Проверка и управление

```powershell
py -3 run.py doctor
py -3 run.py classify "Добавь панель карточек и API"
py -3 install.py --dry-run
py -3 install.py --uninstall
```

На macOS/Linux используйте `python3`. `classify` обращается к платному API. `doctor` проверяет локальную установку, наличие ключа, SDK, каталог, hook и управляемые файлы. Он не проверяет ключ онлайн, доверие hook и доступность моделей.

Каталог настроек: `~/.codex/jev-router/catalog/`. После изменения профилей повторите установку. Изменения каталога сохраняются. Отключение: `enabled: false` в `settings.json`, `JEV_ROUTER_DISABLE=1` или выключение hook в `/hooks`.

Удаление убирает зарегистрированный hook, неизменённые файлы навыка/агентов, управляемое правило в `AGENTS.md` и сохранённый ключ. Остальные инструкции и настройки, изменённые файлы, резервные копии и runtime сохраняются. [Подробности](docs/CONFIGURATION.md).
