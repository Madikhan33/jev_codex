# Промпты классификации Jev

**Здесь находятся тексты, которые действительно отправляются в Jev.** Они не спрятаны в Python-коде. Python собирает вопросы из TOML и проверяет ответы.

| Файл | Что определяет |
| --- | --- |
| [domains.toml](domains.toml) | UI, frontend, backend, БД, инфраструктура, AI, тесты, безопасность, архитектура, инструменты, документация |
| [profiles.toml](profiles.toml) | Критерии выбора Luna / Sol и соответствующие model/effort |
| [routing.toml](routing.toml) | Общие правила, намерение пользователя, возможность разделить работу, неизвестная работа и неопределённость профиля |
| [../data/policy.toml](../data/policy.toml) | Числовые пороги, лимиты текста и таймауты — это настройки кода, не промпты |

## Как выглядит один промпт

Откройте секцию `[categories.backend_api]` в `domains.toml`:

- `question`: конкретный вопрос о серверных endpoints и обработчиках.
- `yes`: что относится к этой категории.
- `no`: граница с клиентским API, БД и инфраструктурой.
- `positive_examples` / `negative_examples`: короткие положительные и близкие отрицательные примеры.
- `profile_notes`: сложность работы внутри этой категории, используется на втором этапе.
- `domain` / `owner`: локальные метки группировки; это не инструкции модели.

UI разделён на `ui_style` (внешний вид существующих элементов) и `ui_layout` (экраны и композиция). `frontend_logic` — локальное поведение, `frontend_api` — связь с API. Сервер разделён на `backend_api`, `backend_logic` и `database`.

## Что получает Jev

В `state` передаётся `request` и явно предоставленный `context`. Это классифицируемые данные.

Первый вызов содержит независимые `Noul`-вопросы по категориям и управляющие вопросы. Несколько категорий могут быть истинными одновременно. Второй вызов содержит `Choice`-вопросы только для принятых категорий.

`instructions` и `criteria` — сами промпты. Отдельная роль «ты эксперт» не нужна. Имена вопросов вроде `work.backend_api` связывают запрос с ответом в коде; смысл категории полностью описан в тексте вопроса. Общие правила включаются в каждый вопрос, поскольку вопросы оцениваются независимо.

Пороги и объединение владельцев применяет Python. Jev не генерирует команды запуска агентов, код, имена файлов или разрешения на изменения.

## Посмотреть точный запрос без ключа

Из корня проекта:

```powershell
py -3 run.py prompts --category ui_layout --category backend_api
py -3 run.py prompts --stage profiles --category backend_api
```

Команды выводят JSON вопросов и не обращаются к API. На macOS/Linux используйте `python3`. `run.py` по умолчанию использует установленную копию; для проверки исходников задайте `JEV_ROUTER_FROM_SOURCE=1`.

Полная читаемая версия: [docs/PROMPTS.md](../../docs/PROMPTS.md). После изменения TOML пересоберите её командой `python scripts/export_prompts.py`.

## Как улучшать качество

1. Уточните включение и ближайшее исключение, например «готовый API подключить к UI» против «создать API на сервере».
2. Добавьте обезличенный пример в `tests/cases.json`: ожидаемые категории, при необходимости `expected_intent` и `acceptable_profiles`.
3. Запустите офлайн-тесты для проверки структуры и контракта.
4. С ключом выполните `uv run eval.py --limit 44` — это платные запросы. Сравните результаты на одних и тех же примерах и модели до/после изменения.

Офлайн-тесты не доказывают семантическую точность Jev. Сокращение текста промпта само по себе также не доказывает ускорение сервиса или сохранение качества.

Установленные промпты находятся в `~/.codex/jev-router/catalog/`. Обновление сохраняет пользовательские изменения; чтобы применить новые тексты из репозитория к старой установке, сравните и перенесите их явно. `routing.toml` добавляется при обновлении старой установки.

Контракты: [TypeSafe Noul](https://docs.typesafe.ai/primitives/noul), [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice).
